# AI 八爪鱼机器人 · 基于小智 ESP32-S3

把小智 AI 的语音大脑装到一个八触手机器人身上。核心思路：**语音层用成熟固件，运动层自己实现，两层通过 MCP 协议解耦。**

## 0. 一句话结论

> 不要给每个动作写轨迹。用 **8 个带相位偏移的正弦振荡器（CPG）** 驱动 8 条触手，再把几个动作注册成 MCP 工具丢给大模型调用。

这样你只需要 3 行数学，就能得到爬行、转向、挥手、跳舞，而且大模型只需要下意图（"往左爬快点"），不用理解逆运动学。

## 1. 为什么不能直接照抄 6 舵机例程

**基线应该换成官方主仓自带的 `main/boards/otto-robot/`**（第三方 fork `xiaozhi-esp32-pet` 可以不再参考）。它是 xiaozhi 官方合并进去的双足机器人适配，里面已经有了：

| 文件 | 作用 | 我们能不能直接抄 |
|---|---|---|
| `oscillator.h/.cc` | 正弦振荡器（CPG），和本目录 `octopus_gait.h` 是同一个思路 | ✅ 直接抄，这是经过社区验证的成熟实现 |
| `otto_movements.h/.cc` | 20+ 预设动作（走、跳、太空步、挥手…） | ✅ 动作编排逻辑可复用 |
| `power_manager.h` | 电源与电量管理 | ✅ 可复用 |
| `websocket_control_server.cc` | 微信小程序直连控制 | ✅ 调试阶段很有用 |
| `config.h` | 6 个舵机各占一个 GPIO，走 **LEDC 直驱** | ❌ **这一条必须改** |

为什么最后一条必须改：ESP32-S3 的 LEDC **只有 8 个通道**。Otto 用 6 个刚好够，所以官方那样跑没问题；但方案 B 要 16 路，直接撞墙。所以这里的分工是——

> **保留 Otto 的振荡器和动作框架，把底层的 `Write()` 从 LEDC 换成 PCA9685 的 I2C 写入，`SERVO_COUNT` 从 6 改到 16。**

这也是本目录 `octopus_bus.h` 存在的意义。注意别混淆：不是说 LEDC 不能用，而是**它最多撑到 8 路**。

剩下的两个通用理由仍然成立：舵机数量多时 PCA9685 自带振荡器，不占 CPU 也不和 I2S 音频 DMA 抢定时器；且舵机电流可以完全从 V+ 独立引入，不经过 ESP32。

## 2. 三档方案选型

| | 方案 A 入门 | **方案 B 推荐** | 方案 C 硬核 |
|---|---|---|---|
| 每条触手自由度 | 1（偏航） | 2（偏航+俯仰） | 3（腱绳连续体） |
| 舵机总数 | 8 | 16 | 24 |
| PCA9685 数量 | 1 | 1 | 2 |
| 能不能抬起 | 不能，只能蹭着走 | 能，可真爬行 | 能，还能卷曲抓握 |
| 结构材料 | PLA 刚性件 | PLA 万向节 + TPU 触手尖 | TPU 蛇骨 + 凯夫拉线 |
| 舵机成本 | ~60 元 | ~150 元 | ~250 元 |
| 调试难度 | 低 | 中 | 高（要处理线摩擦、预张力、回弹） |

**建议从 B 起步。** 方案 A 做出来不太像章鱼（不能抬起＝没有"步态"可言），方案 C 的调参量会让你怀疑人生。代码里三种都支持，改一个枚举就行：

```cpp
OctopusBody body;
body.Init(octo::RigType::kDual16, &i2c_dev, octo::I2cWriteIdf);
body.SoftHome();
body.Start();
```

## 4. 接线

```
ESP32-S3                外设
─────────────────────────────────────────────
GPIO 8  (SDA)  ──┬──→  PCA9685 SDA
GPIO 9  (SCL)  ──┴──→  PCA9685 SCL
                  └──→  OLED SDA/SCL（同总线，互不冲突）

GPIO 5  (BCLK) ──→  INMP441 SCK        音频输入
GPIO 4  (WS)   ──→  INMP441 WS
GPIO 6  (DIN)  ──→  INMP441 SD

GPIO 15 (BCLK) ──→  MAX98357A BCLK     音频输出
GPIO 16 (LRC)  ──→  MAX98357A LRC
GPIO 7  (DIN)  ──→  MAX98357A DIN

3V3 / GND      ──→  PCA9685 VCC（只给芯片逻辑供电！）
─────────────────────────────────────────────
电池 7.4V  ──→  XL4015 降压  ──→  6V ──→  PCA9685 V+ 螺丝端子 ──→ 16 路舵机
                              └──→  5V ──→  ESP32 的 VIN/5V 引脚
                              并且三者必须共地（ GND 全部连一起 ）
```

**引脚安全提醒：** 避开 GPIO 19/20（USB-JTAG）、0/45/46（启动 strapping）、26–37（Flash/PSRAM 占用）。GPIO 8/9 做 I2C 很安全，是社区验证过的选择。

**电源三原则（踩了必炸）：**
1. 舵机的 **V+ 绝对不能** 从 ESP32 的 3V3 或 5V 引脚取电，必须走 PCA9685 的螺丝端子。
2. 外部电源 GND、ESP32 GND、PCA9685 GND **必须全部共地**，否则 PWM 没有参考电平，舵机会抽搐。
3. 每条舵机旁边并一个 220µF 电解电容，就近补偿瞬态电流。

## 5. 固件集成步骤

```bash
git clone https://github.com/78/xiaozhi-esp32.git
cd xiaozhi-esp32
# 建议同时对照 xiaozhi-esp32-pet 这个 fork，它把 OLED 表情 / MT3608 升压 / 舵机分时启动
# 这些外围实践都做完了，直接抄它的 BSP 组织方式最省事
```

1. 复制板级目录：`main/boards/xiaozhi-pet/` → `main/boards/octopus/`
2. 修改 `config.h` 里的引脚和 I2C 地址（第二块 PCA9685 地址是 `0x41`）
3. 把本目录的 `octopus_gait.h` / `octopus_bus.h` / `octopus_body.h` / `octopus_mcp.cpp` 拷进去
4. 在该板的 `CMakeLists.txt` 里加上：`idf_component_register(... SRCS "... octopus_mcp.cpp" ...)`
5. 在板的 `Initialize()` 末尾依次调用 `Init()` → `SoftHome()` → `Start()` → `RegisterOctopusTools()`
6. 烧录、配网，去 [xiaozhi.me](https://xiaozhi.me) 控制台确认设备在线，并检查智能体是否能看到 `self.octopus.*` 这几个工具

> `octopus_mcp.cpp` 用的 `AddTool` 签名是 v2.x 的写法。xiaozhi 迭代很快，如果你的 fork 编译报错，对着 `main/boards/common/` 里任意一个板子的 `AddTool` 调用改一下参数包就行 —— 运动层代码一行都不用动。

## 6. 文件说明

| 文件 | 作用 | 依赖硬件 |
|---|---|---|
| `octopus_gait.h` | 纯数学：CPG 振荡器阵列 + pose 插值。**可在 PC 上直接单测** | 无 |
| `octopus_bus.h` | PCA9685 驱动 + 软启动 + 角速度限速 | ESP-IDF 或 Arduino |
| `octopus_body.h` | 运动控制器，开 50Hz 任务，支持三种 RigType | FreeRTOS |
| `octopus_mcp.cpp` | 把动作注册成 MCP 工具，供大模型调用 | xiaozhi-esp32 |

## 7. 建议的推进顺序（别跳步）

| 阶段 | 目标 | 预计 |
|---|---|---|
| 0 | 小智语音链路跑通，一个舵机都不接 | 半天 |
| 1 | 1 个舵机 + 最小 MCP 工具，验证"说话能动手" | 半天 |
| 2 | 上 PCA9685 + 独立电源，驱动 4 路 | 1 天 |
| 3 | 打印结构件，组装成 16 路八爪鱼 | 2–3 天 |
| 4 | **调 CPG 参数**（最花时间的部分） | 持续 |
| 5 | 升级：总线舵机 / IMU 姿态闭环 | 后续 |

第 4 步才是真正决定它"像不像章鱼"的地方。先用一组在线的参数去感受这三个量怎么影响观感，调到满意了再拿去填 `GaitParams`。经验起点：`freq=0.6, yaw_amp=38, duty=0.65, phase=45`。

## 8. 已知的坑

- **别设错 PWM 频率**：PCA9685 上电默认约 200Hz，舵机必须用 `setPWMFreq(50)`。
- **必须分时/限速上电**：16 路同时跳到中位会瞬间拉塌电源。代码里 `SoftHome()` 和 `SetMaxRate()` 就是干这个的，实测能把峰值电流从 2.3A 压到 1.3A 左右。
- **音频会被自己的运动干扰**：舵机噪音会被麦克风收录，正在做大动作时尤其明显。建议做大动作时临时提高唤醒/VAD 阈值，或者短暂推迟 barge-in 检测。
- **麦克风和喇叭保持 5cm 以上**，否则直接啸叫。
- **每条触手要单独标定中位**：几何上装不可能是完美的，用 `bank_.SetTrim(ch, ±x)` 在软件里补偿，别去拆结构。

## 9. 升级方向

做到能爬之后，最值得花钱的一步是**把 PWM 舵机换成串口总线舵机**（Feetech SCS/STS 系列、Waveshare SC09）。24 个舵机只需要一根 UART + 一条电源总线串起来，还能**回读角度和负载电流**，可以做真正的力控。开源项目 shoggoth-mini 的软体触手就是这么做的（3 个 STS3215 + 钓鱼线）。缺点是单价翻倍。

再往上可以加 IMU（MPU6050）做姿态闭环，让它在被推歪时能自己撑回来。
