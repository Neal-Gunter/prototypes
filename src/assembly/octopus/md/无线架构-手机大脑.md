# 无线架构：手机当大脑，八爪鱼身体无线联动

> 你的目标：**手机做大脑（对话 / AI / 决策），身体用蓝牙或 WiFi 无线连接，八爪鱼结构（8 条触手）不变。**
> 这份文档专门讲这套"无线手机大脑"架构，和 `采购清单-零基础.md`、`README.md` 配合看。

---

## 0. 结论先说

这个设想**完全成立**，而且比"买实战派插线"更优雅——身体和手机之间**零线缆**，手机算力强、有屏有摄像头，身体只管运动。

但有一个**必须提前知道的现实**：相比之前那份"实战派网页烧录即用"的路线，无线手机大脑是**更进阶**的玩法。难点不在硬件（ESP32 + PCA9685 + 电池是标准件），而在**软件那一层**——怎么让手机的 AI 对话"变成"驱动舵机的指令。下面会把它拆成可分步实现的几档。

---

## 1. 架构一句话

```
手机（小智客户端 / 本地AI）  ──BLE 或 WiFi──▶  ESP32-S3 身体控制器
                                               │  （跑 CPG 步态引擎，见 octopus_gait.h）
                                               ▼  I2C
                                            PCA9685 ──16 路 PWM──▶ 16× MG90S（8 条触手）
                                               ▲
                                        自带锂电池（2S + 降压）
```

身体**自带电池、自带 ESP32**，和手机之间没有任何线。八爪鱼结构完全不变。

---

## 2. 反直觉的好消息：身体固件反而更简单了

之前的"实战派方案"里，ESP32 要编译**整套小智固件**（麦克风采集 → 音频编解码 → WebSocket → 大模型 → TTS → 喇叭播放），那套环境对新手很劝退。

现在手机当大脑，**身体 ESP32 完全不用管对话**，它只做一件事：

> 收到一句高级指令（比如 `"WALK -60 4"` = 往左 60°、速度 4），在本地跑 CPG 步态，算出 16 路舵机角度，通过 PCA9685 输出。

所以身体固件只是一个**轻量 BLE/WiFi 舵机执行器 + 我们的步态引擎**，比编译整个小智容易得多，用 Arduino IDE 就能写，不需要 ESP-IDF。

---

## 3. 唯一真正的难点：大脑怎么"指挥"身体（对话 → 动作）

手机上的 AI 说了一堆话，怎么变成舵机动作？这是整个项目唯一的编程活。三档走法，**从零代码到写程序**：

| 档位 | 怎么动 | 需要写代码吗 | 适合阶段 |
|---|---|---|---|
| **A 手动蓝牙（起步）** | 小智客户端负责聊天；另开一个蓝牙串口 App（如 Serial Bluetooth Terminal），手动点按钮发 `"WALK"` / `"WAVE"` | **零代码** | 先验证身体能听指挥 |
| **B 小智 MCP 自动（进阶）** | 给手机侧智能体注册一个 `octopus_control(action,params)` 工具，LLM 决定调用时，由一个小程序把指令通过 BLE/WiFi 发给身体 | 需要写手机侧桥接 | 想要"说走就走" |
| **C 自写 App（最完整）** | 一个 Flutter 页面里既有小智对话、又有 BLE 发送 | 需要写 App | 终极形态 |

**强烈建议从 A 起步**：身体固件三档完全一样，只是"谁发指令"不同。先把身体用蓝牙手动控起来，再把对话接上去，风险拆成两半。

> 关于 B：小智官方生态里 `otto-robot` 已有 `websocket_control_server`（小程序直连控制），它的思路可以直接借——把"WebSocket"换成"BLE"，身体这边代码几乎一致。

### ✅ 方案 A 已落地（用户已选）

用户选了 A。已交付两套可直接用的文件：

- **`body_firmware_A.ino`** —— 身体端固件（Arduino）。在 `OctopusBody` 外面套了一个蓝牙串口壳，收到 `WALK`/`LEFT`/`STOP`/`WAVE`/`PULSE`/`GAIT` 等指令就驱动 CPG 步态。把本 `.ino` 和 `octopus_gait.h`/`octopus_bus.h`/`octopus_body.h` 放同一文件夹即可编译。
- **`手机控制指南-A方案.md`** —— 手机端零代码操作：装哪个 App、怎么配对、发什么指令、怎么现场调步态参数。

指令速查：

| 手机发 | 八爪鱼做 |
|---|---|
| `WALK` / `GO` | 开始爬行 |
| `LEFT` / `RIGHT` | 左转 / 右转 |
| `STOP` / `REST` | 停，回中位 |
| `WAVE 3` | 第 3 号触手挥一下（0~7） |
| `PULSE 3` | 缩成一团 3 次 |
| `GAIT f=0.6 yaw=38 lift=20 phase=45 duty=0.65` | 现场调步态（不发用默认） |

> 注意：方案 A 里"聊天"和"控制"是两套独立 App——小智客户端负责陪聊，Serial Bluetooth Terminal 负责发动作。两者暂不联动，正是为了先把身体跑顺。

## 4. 核心设计铁律：步态引擎放在身体 ESP32 上

**手机永远只发"动词"，不碰任何一个舵机角度。** 例如：

```
手机发：  WALK -60 4        （往左偏 60°，速度 4）
身体算：  8 个正弦振荡器 + 相位偏移 → 16 路角度 → PCA9685
```

为什么这么分：

- **延迟低**：手机不用算数学，指令只有十几个字节
- **手机简单**：不用移植 CPG 代码，安卓端零负担
- **断连不死**：蓝牙断了，身体原地停住，不会乱抖
- **可直接复用** `octopus_gait.h` / `octopus_body.h`，一行都不用改

---

## 5. 无线通信怎么选：BLE vs WiFi

| | BLE 蓝牙（**推荐**） | WiFi |
|---|---|---|
| 功耗 | 极低，适合电池身体 | 高，明显缩短续航 |
| 距离 | ~10 米 | 取决于路由器，几十米 |
| 是否需要路由器 | 不需要，直连 | 需要（或身体开热点） |
| 手机兼容性 | 原生支持，App 多 | 需要联网 |
| 适合场景 | **电池供电、要 roam** | 桌面固定、要 OTA / 传传感器数据 |

**电池身体用 BLE 最划算。** 如果身体长期放桌面、你想顺手做 OTA 升级或回传 IMU 数据，再上 WiFi（身体开 soft-AP，手机连它）。

> 注意：2.4G WiFi 和 BLE 同频，身体同时开两者会互相干扰。**用 BLE 就把 WiFi 关掉。**

---

## 6. 供电：身体现在要自己背电池（和有线版最大的不同）

有线版是外接 5V6A 适配器；无线版身体必须自带电池。重量和电流要重算：

**重量重算（无线版）**

| 部件 | 重量 |
|---|---|
| 16× MG90S | 214 g |
| 最小 ESP32-S3 板（替代实战派） | ~10 g |
| PCA9685 | 15 g |
| 2S 7.4V 锂电池 + 降压 + 充电模块 | ~85 g |
| PLA 结构件 | 150~250 g |
| 线材端子 | 20 g |
| **合计** | **约 550~600 g** |

比有线版（~510g，含实战派）略重，主要来自电池。

**电池方案（推荐）**

```
2S 锂聚合物电池 7.4V 2000mAh  ──▶  XL4015 降压到 6V  ──▶  PCA9685 V+  ──▶ 16 路舵机
                                  └─▶  5V（给 ESP32 的 VIN）
所有 GND 共地
```

- **舵机用 6V 不用 5V**：MG90S 扭矩从 1.8 提到 2.2+ kg·cm，白赚 20~30%（标称 4.8~6.0V，合规）
- **电流**：16 舵机活动平均 3~5A 峰值，2000mAh 大约能活动 20~40 分钟（你是一阵阵动，不是常转）
- **安全（必看）**：Li-Po 过放 / 短路会鼓包起火。务必用**带保护板**的电池，并在 ESP32 上做**低压截止**（读电池电压，低于 6.4V 就停运动、只留通信）——`power_manager.h` 的思路可复用

## 7. 力矩余量再算一次（无线版更要命）

身体 ~580g，8 条触手着地、各靠俯仰舵机承重，触地在约 6cm 处：

- MG90S @6V 持续输出 ≈ 1000~1200 g（标称堵转值 2.2kg·cm 的 1/2）
- 爬行冲击载荷约 2~3 倍 → 需要 1000~1500 g

**结论：能撑，但余量薄。** 想让它动得稳，做这四件事：

1. **舵机 6V 供电**（上面已写）
2. **触手 ≤ 8cm**，别更长
3. **结构件打薄**，PLA 填充率 15~20%
4. **目标定为"表达型轻爬"**，而非"负重狂奔"——八爪鱼的灵魂是扭动、挥舞、反应，不是越野

如果将来想让它真正稳健地走，同尺寸换 **MG92B**（~2.5~3 kg·cm @6V，重量相近）是最省事的升级，不用改结构。

## 8. 身体 ESP32 选哪块（和采购清单原来不同了）

之前清单让你买**立创实战派 ¥148**，因为它把屏 / 麦 / 喇全做了，适合"板上对话"。

现在**手机当大脑，身体不需要屏麦喇**——实战派那些集成件全浪费了，还更重更贵。身体改用：

| 物品 | 价格 | 说明 |
|---|---|---|
| **最小 ESP32-S3 开发板**（如 ESP32-S3-DevKitC-1 或兼容克隆） | ¥25~35 | 只要 I2C + BLE，越小越轻越好 |
| （可选）ESP32-C3 最小板 | ¥15~20 | 更小更省电，但 GPIO 少、社区例程少，新手不建议 |

> 实战派现在变成**可选项**：只有当你想让"身体脱离手机也能对话"时才需要它。默认路线不需要买。

## 9. 推荐推进顺序（把风险拆成小块）

| 阶段 | 目标 | 验证什么 |
|---|---|---|
| 0 | 最小 S3 板 + Arduino，BLE 收到 `"WALK"` 点亮 LED | 无线链路通了 |
| 1 | + PCA9685 + 1 个舵机，BLE 收到指令舵机转 | 执行器通了 |
| 2 | 16 路 + 电池 + 打印结构，手机手动控八爪鱼动 | 身体完整可动 |
| 3 | 手机装小智客户端，能聊天（暂不管身体） | 大脑通了 |
| 4 | 接 bridge（方案 B/C），让"说话"触发动作 | 大脑指挥身体 |
| 5 | 调 CPG 参数（最花时间） | 像不像章鱼 |

**第 0~2 步完全不用碰小智 / 不用碰对话**，先把"无线身体"跑顺。这比一上来就整合 AI 稳得多。

## 10. 身体固件骨架（BLE UART + CPG，可复用现有头文件）

Arduino 伪代码，落到 `main/boards/octopus/` 时换成 ESP-IDF 也行：

```cpp
#include <BLEDevice.h>
#include <BLEServer.h>
#include "octopus_gait.h"   // 现有：CPG 振荡器
#include "octopus_bus.h"    // 现有：PCA9685 驱动
#include "octopus_body.h"   // 现有：运动控制器

OctopusBody body;
String cmdBuffer;

// BLE 收到 "WALK -60 4" / "WAVE" / "STOP" 之类，写进 cmdBuffer
void onBleReceive(String s) { cmdBuffer = s; }

void loop() {
  if (cmdBuffer.length()) {
    if (cmdBuffer.startsWith("WALK")) {
      int dir = ..., spd = ...;            // 解析参数
      GaitParams p; p.freq = spd * 0.15; p.yaw_amp = 38; p.phase = dir;
      body.SetGaitParams(p); body.Start();
    } else if (cmdBuffer == "STOP") {
      body.Stop();
    }
    cmdBuffer = "";
  }
  body.Tick();   // 50Hz：CPG 算角度 → PCA9685 输出
}
```

也就是说，**现有 `octopus_gait.h` / `octopus_body.h` / `octopus_bus.h` 三个文件直接复用**，无线版只多了一个 BLE 接收 + 指令解析的壳。

## 11. 无线专属的坑

- **蓝牙配对 / 重连**：手机息屏后 BLE 可能被系统断掉，身体端要做自动重连 + 超时软停机
- **电池低压**：电压一掉，舵机抖、ESP32 重启。必须低压截止（见第 6 节）
- **WiFi/BLE 同频干扰**：用 BLE 就别开 WiFi
- **上电冲击**：16 路同时回中拉塌电源，沿用 `SoftHome()` 分时启动（峰值 2.3A → 1.3A）
- **断连保护**：收不到心跳就停运动，避免"失控狂舞"
